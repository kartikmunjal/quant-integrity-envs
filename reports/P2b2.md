## Pre-gate findings and interpretation

The required decomposition was written first in `reports/P2b2_design.md`. The
old 0.4 reward came from an unchanged signal-mean hit despite an incorrect return;
old replay credit required both numbers and did not repair that additive loophole.
The new reward combines maximum relative error across both outputs and both
independent executions. Full credit remains within the frozen 1e-4 tolerance;
smoothstep quality reaches zero at 0.01 relative error. Frozen 0.8/0.2 weights
remain. No preregistered threshold, weight, seed partition, generator parameter,
held-out family or tolerance was edited.

The task constructor searches deterministic reporting-window dates and requires
at least 0.02 relative separation from a naive availability-ignoring answer on
every emitted case, including T4. Candidate date search is construction, not
removal of episodes: a seed with no candidate is a recorded gate failure. The
P1 market generator stays frozen; E1 task construction is separately identified
by the committed source/image freeze. Presentation context distinguishes tier
hints, grouped vintages, summary decoys and clean newest-first controls; empirical
human/model difficulty separation is unmeasured.

Design choices used only E1 seeds 1001000..1001999, with design replay restricted
to the same range. The fresh gate uses primary seeds 1002000..1002499 (first 50
per tier for policy-cell statistics) and replay seeds 1003000..1009999. Existing
unmodified tests for other environments retain their own previous dev seeds.
No sealed-test evaluation, model baseline, training or model API call was run.

The legacy direct-answer APIs now return zero even for exact values accompanied
by a self-reported availability flag. Only the checked Task lifecycle can produce
positive E1 rewards. All actual runtime read APIs are traced and bounded; source
transfer rejects symlinks/special files and oversize files before transfer, limits
the read itself, and checks received length again. Initial nonzero solver status
is retained and zeroed. Invalid/flagged solver cases may stop before replay, with
absence retained as evidence of rejection rather than omitted from the table.

The normal v1 `eval` CLI succeeded on a design seed, with a full lifecycle, three
distinct containers, reward 1.0, zero model calls and uploads disabled, saved in
`logs/p2b2_cli.json`. Only local scripted execution is supported in this phase;
unsupported model harnesses and remote/generic runtimes fail closed. Hub
installation does not automatically supply this Docker boundary or private host
storage. Current official references and the correction that the pinned wheel
has no IsolatedVerifierEnv are in COMPAT.md. No Hub package was published.
