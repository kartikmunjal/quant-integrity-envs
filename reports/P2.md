## Independent reviewer sessions

Independent reviewer sessions were used for all three verifiers: `/root/review_e1`,
`/root/review_e5`, and `/root/review_e6`. They made no edits.

All three reviewers found the same blocking class of issue: the committed code is a deterministic
verifier core, not yet a complete Verifiers v1 taskset/runtime. In particular, the path guards and
cheater simulations are not wired to real container mounts, protected verifier-only oracle
staging, canary-read evidence, immutable harness evidence, network denial, declared artifact
transfer, or agent-facing tools and task artifacts. Therefore the mount tests prove the behavior
of the declared path function, but not a deployed sandbox configuration. Calling that a completed
environment would overstate what was built.

Reviewers also identified semantic shortcomings: E1 availability discipline remains reported by
the answer rather than established through code re-execution/access evidence; E5's current
calculation uses an equal-weight market return rather than a submitted gross signal and does not
fully enforce capacity; E6 labels generated corporate-action events as anomalies rather than
planting and exposing corrupted records for reconciliation. The later hardening fixed non-finite
acceptance and vacuous wrong-answer schemas, but did not silently paper over these larger issues.
