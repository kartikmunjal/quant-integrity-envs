## Multi-step boundary

One inspected solver container persists for an episode; commands execute as separate bounded solver-UID processes. Files persist, Python process state does not. Network remains none, root filesystem read-only, one declared work bind, fixed immutable image, fixed pids/memory/CPU limits, traced solver commands, canary/harness protections, and host-only grading. The host client and its credentials never run inside or enter the container.

Existing trusted runtime.write is used only by unchanged task setup, before model actions. Model-influenced submission writes use audited solver-UID helpers at fixed /work-root filenames with O_NOFOLLOW; their parent is the immutable mount point. File reads/listing use componentwise dirfd and O_NOFOLLOW confinement. Numeric write-directory descriptors that lack a resolved trace annotation are refused because the existing syscall filter cannot safely reconstruct dup2/close state. File tools reject traversal, nonregular files, links, and paths outside /work. The adapter adds conservative write-path trace auditing for implicit writable container locations such as /dev/shm. Uncertain, truncated or unsupported audit evidence ends the episode rather than permitting continued execution. The intended contract requires destruction before continuation after host timeout, transport failure or cancellation. The adapter shields and joins its own solver provisioning and never applies the model deadline to native grading. The native helper's general cancellation-ordering limitation remains documented above. Native scoring and primary/fresh replay remain unchanged.

Each model command first clears its inherited environment, then supplies only the fixed public PATH=/usr/local/bin:/usr/bin:/bin, LANG=C.UTF-8 and PYTHONDONTWRITEBYTECODE=1. This preserves existing programs that launch Python subprocesses while preventing inherited host values. Host credentials are never mounted, passed as solver arguments, or included in container environment. This prevents host-environment exposure; it does not claim to detect every in-process getenv query. Containers necessarily contain readable system libraries; work-file tools are confined, while ordinary interpreter/library reads remain necessary for command execution. No remote or generic runtime is certified.

## Process-allowance hardening

P5b keeps the fixed 32-process limit. Host-only snapshots bind the inspected full container ID/init PID to its local cgroup-v2 path, actual pids.max=32 and cumulative pids.events:max. Only a fresh positive delta with a healthy daemon authorizes the new policy classification. The host confirms container removal before recording the policy flag/zero; subsequent native transfers reject only this confirmed exhaustion outcome. Genuine infrastructure failures retain their classification without valid proof; known exhaustion with unusable daemon health cannot return a trusted success.

This requires a local daemon with matching host PID/cgroup visibility, tested here on WSL2/cgroup v2. No process starts inside the container for observation and no privilege, mount, UID, network, memory or CPU change is made. Kernel counters cannot be forged by the solver; unavailable evidence never authorizes a policy zero. ## Spend and pilot authorization

Prices are a committed empty template; owner-supplied prices are required later. Actual costs use returned token usage and Decimal prices, with the caps and 80-percent stopping rule from prereg.yaml via scripts/budget_gate.py. Locked outstanding reservations cover conservative call bounds and are not recorded as paid spend. Lost responses retain unresolved reservations and stop further dispatch. Actual usage exceeding a reservation is recorded in full and stops; it is never concealed as a refused cost. Such a provider-bound violation is a limitation requiring owner reconciliation, not a proof that arbitrary provider billing can never exceed its declared limits.

The pilot entrypoint remains locked through P5b even when --confirm-spend is supplied. It must reject before reading a credential or opening a connection. No spend-cap override exists. A later owner-authorized phase must review/unlock the provider path, fill prices, and reconcile any outstanding reservation. Filling a key variable alone cannot enable calls. Planned default is two episodes per environment/tier cell (32 per model across four environments), satisfying the preregistered 20-episode pilot floor; default seed windows must be checked against all historical gate populations before use.

Baseline projections use observed token totals divided by observed episode counts and owner prices. They preserve frozen episode counts and at least two API plus two open models. Extra baseline models are removed before reducing training seeds. Training GPU projection requires a separate measured per-seed amount; it is never invented from baseline API tokens. Reducing training seeds cannot fix excessive baseline API cost. Projections report unavailable components explicitly and respect the 80-percent stop bound as well as hard caps.

## Prompts, transcripts and equivalence

Per-environment prompts and tool descriptions are content-hashed in an append-only prompt manifest. Later changes require a new dev-only manifest entry; old entries must remain, and sealed outcomes must never select prompts. No prompt is tuned on model results in P5a.

Transcripts contain bounded, hashed messages, tool calls, visible outputs, token counts, time, reward, termination reason and hack monitors. Known credentials are redacted before recording. Full credentials, HTTP authorization headers, raw provider errors and host environment dumps are never recorded. Hashes make truncation and storage scope explicit; a bounded transcript must not silently drop a whole episode.

Small T1 mock-oracle engineering smokes were compared with the existing scripted harness on identical dev inputs. Round 2 commits exact dev-only cohorts before execution: oracle 50/tier/environment, at least five wrong policies and every existing cheater 10/tier/environment; boundary 176, sentinel 16, stress 1000 at concurrency 8. The P5b rerun preserves those exact rows and passes boundary, sentinel, all semantic pairs and all 1,000 mock stress episodes. Batch evidence and current outcomes are recorded in reports/P5b.md. Semantic primary/replay records include answers, numerical results, status, flags and submitted source identity. Separate fresh rollouts necessarily have different container IDs, command trace hashes and timing: those operational fields are excluded from equivalence, with original provenance retained separately. Numeric comparisons use 1e-12. This is mock tool-path equivalence, not evidence that a real model follows instructions or succeeds at research.

A later pilot measures reward density, turns, tokens, cost and hack monitors on dev seeds. It will not estimate sealed-test performance, training transfer, broad research integrity, or real-market usefulness. Infrastructure validation results and any unsupported boundary will be recorded in reports/P5b.md before STOP.

Any nonzero tool command is terminal in this adapter, preserving the existing runtime policy-failure semantics. This allows sequences of successful commands but does not certify recovery after a failed debugging command. A future recoverable-error design would require explicit review of the shared policy ledger; no such change is made here.
