# P5a model harness: STOP — shared lifecycle change required

**This is an uncertified infrastructure prototype. P5a did not pass.** The existing runtime supports ordinary sequential solver commands, but the required whole-episode deadline and no-leaked-container contract is not established for native primary/replay startup. The owner forbids a shared-runtime change in this task, so the full equivalence, live boundary and 1000-episode stress batches were not started. Provider calls and paid pilot execution remain locked.

An independent pure-mock diagnostic invokes the unchanged shared `execute_program` helper and produces `remove_before_create` followed by `created` when a simulated daemon completes after client cancellation. This is a demonstrated ordering permitted by that helper, **not an observed real Docker leak**. See [evidence](../results/p5a_runtime_blocker.json) and [P5a report](../reports/P5a.md). Successful ordinary smokes and passing component tests do not close this gap.

P5a builds infrastructure using synthetic dev cases and mock responses. Provider calls are locked, real key values must not be inspected, and the paid pilot cannot run in this task. The only HTTP test is an explicitly enabled loopback fake server using a deliberately planted fake credential. Empty committed prices cannot authorize any call. No baseline, training, sealed evaluation, or E3 experiment is performed.

The implementation reuses the unchanged checked runtime and unchanged E1, E2, E5 and E6 task setup/finalize/reward implementations. A separate v1 Env adapter selects the model harness instead of weakening the existing scripted-only Env checks. The E3 prototype on main is unvalidated and is skipped; the separate e3-redesign branch is not silently merged or activated.

## Multi-step boundary

One inspected solver container persists for an episode; commands execute as separate bounded solver-UID processes. Files persist, Python process state does not. Network remains none, root filesystem read-only, one declared work bind, fixed immutable image, fixed pids/memory/CPU limits, traced solver commands, canary/harness protections, and host-only grading. The host client and its credentials never run inside or enter the container.

Existing trusted runtime.write is used only by unchanged task setup, before model actions. Model-influenced submission writes use audited solver-UID helpers at fixed /work-root filenames with O_NOFOLLOW; their parent is the immutable mount point. File reads/listing use componentwise dirfd and O_NOFOLLOW confinement. Numeric write-directory descriptors that lack a resolved trace annotation are refused because the existing syscall filter cannot safely reconstruct dup2/close state. File tools reject traversal, nonregular files, links, and paths outside /work. The adapter adds conservative write-path trace auditing for implicit writable container locations such as /dev/shm. Uncertain, truncated or unsupported audit evidence ends the episode rather than permitting continued execution. The intended contract requires destruction before continuation after host timeout, transport failure or cancellation. The adapter can shield and join its own solver provisioning, but cannot guarantee this for the unchanged native grading helper; that is the STOP blocker. Source finalization and primary/fresh replay remain unchanged.

Each model command first clears its inherited environment, then supplies only the fixed public PATH=/usr/local/bin:/usr/bin:/bin, LANG=C.UTF-8 and PYTHONDONTWRITEBYTECODE=1. This preserves existing programs that launch Python subprocesses while preventing inherited host values. Host credentials are never mounted, passed as solver arguments, or included in container environment. This prevents host-environment exposure; it does not claim to detect every in-process getenv query. Containers necessarily contain readable system libraries; work-file tools are confined, while ordinary interpreter/library reads remain necessary for command execution. No remote or generic runtime is certified.

## Limits and termination

Defaults committed before validation: 16 model turns, 2048 completion tokens per turn, 32768 total tokens, 180 seconds per episode, 16384 bytes per visible tool output, and 2097152 transcript bytes. Counts and byte bounds are positive integers; timeout is positive and finite. The runtime's existing 20-second command timeout and resource constraints remain in force. Component tests cover defined zeros and recorded reasons for non-submission, token/turn limits and loop timeouts. The adapter adds a whole-workflow deadline and cleanup-failure precedence, but its coverage cannot certify cancellation during native grading startup. Cleanup is intended to be unconditional; cancellation ordering in the shared helper remains unmet.

## Spend and pilot authorization

Prices are a committed empty template; owner-supplied prices are required later. Actual costs use returned token usage and Decimal prices, with the caps and 80-percent stopping rule from prereg.yaml via scripts/budget_gate.py. Locked outstanding reservations cover conservative call bounds and are not recorded as paid spend. Lost responses retain unresolved reservations and stop further dispatch. Actual usage exceeding a reservation is recorded in full and stops; it is never concealed as a refused cost. Such a provider-bound violation is a limitation requiring owner reconciliation, not a proof that arbitrary provider billing can never exceed its declared limits.

The pilot entrypoint remains locked in P5a even when --confirm-spend is supplied. It must reject before reading a credential or opening a connection. No spend-cap override exists. A later owner-authorized phase must review/unlock the provider path, fill prices, and reconcile any outstanding reservation. Filling a key variable alone cannot enable calls. Planned default is two episodes per environment/tier cell (32 per model across four environments), satisfying the preregistered 20-episode pilot floor; default seed windows must be checked against all historical gate populations before use.

Baseline projections use observed token totals divided by observed episode counts and owner prices. They preserve frozen episode counts and at least two API plus two open models. Extra baseline models are removed before reducing training seeds. Training GPU projection requires a separate measured per-seed amount; it is never invented from baseline API tokens. Reducing training seeds cannot fix excessive baseline API cost. Projections report unavailable components explicitly and respect the 80-percent stop bound as well as hard caps.

## Prompts, transcripts and equivalence

Per-environment prompts and tool descriptions are content-hashed in an append-only prompt manifest. Later changes require a new dev-only manifest entry; old entries must remain, and sealed outcomes must never select prompts. No prompt is tuned on model results in P5a.

Transcripts contain bounded, hashed messages, tool calls, visible outputs, token counts, time, reward, termination reason and hack monitors. Known credentials are redacted before recording. Full credentials, HTTP authorization headers, raw provider errors and host environment dumps are never recorded. Hashes make truncation and storage scope explicit; a bounded transcript must not silently drop a whole episode.

Small T1 mock-oracle engineering smokes were compared with the existing scripted harness on identical dev inputs. The full oracle, wrong-policy and cheater matrix is authored but NOT RUN because of the STOP blocker. Semantic primary/replay records include answers, numerical results, status, flags and submitted source identity. Separate fresh rollouts necessarily have different container IDs, command trace hashes and timing: those operational fields are excluded from equivalence, with original provenance retained separately. Numeric comparisons use 1e-12. This is mock tool-path equivalence, not evidence that a real model follows instructions or succeeds at research.

A later pilot measures reward density, turns, tokens, cost and hack monitors on dev seeds. It will not estimate sealed-test performance, training transfer, broad research integrity, or real-market usefulness. Infrastructure validation results and any unsupported boundary will be recorded in reports/P5a.md before STOP.

Any nonzero tool command is terminal in this adapter, preserving the existing runtime policy-failure semantics. This allows sequences of successful commands but does not certify recovery after a failed debugging command. A future recoverable-error design would require explicit review of the shared policy ledger; no such change is made here.

## Required shared change — design only, not implemented

1. Add a shared lifecycle scope used by every `CheckedRuntime` owner, including `execute_program`, rather than shielding only the model Env. Retain a provisioning task and stable resource identity through `NEW → PROVISIONING → RUNNING → STOPPING → STOPPED` states.
2. On cancellation, join the pending daemon/provisioning outcome before final removal. A lost transport response is uncertain: reconcile by the preallocated unique name/ID and daemon state. One `rm` returning “no such container” while creation remains unresolved must never mark cleanup complete.
3. Shield and join teardown, make it idempotent, and record definite removal. A cleanup or reconciliation failure remains an infrastructure failure/incomplete attempt; do not turn it into a clean timeout zero or permit a new rollout retry before cleanup is established.
4. Propagate an episode cancellation/deadline token through the shared execution scope. Check it before every new primary/replay/poison stage. Expiry permits cleanup only; it must not launch another replay or continue model actions. Preserve the original cancellation after joined cleanup.
5. Apply the same rules to command cancellation: a killed Docker client is not proof that the solver command or daemon-side operation stopped. Source finalization must not resume after an uncertain command.
6. Write independent lifecycle regressions first for cancellation during create/start/inspect/transfers/command/status/teardown, then test real Docker deadline expiry at solver and grading stages, all-container cleanup and the requested concurrency-8 stress. Re-run the full mock/scripted matrix against the approved new runtime version. Preserve historical runtime hashes, freezes and gate evidence; no financial thresholds, verifier semantics, network policy, mounts or privileges need to be relaxed.

Shielding the entire grading coroutine and waiting for it after expiry is not a substitute for the requested deadline: it can continue primary/replay work after expiry. Inspecting private attempt lists or monkeypatching the shared runtime from the adapter is not a supported atomic lifecycle API. The owner must authorize the shared change in a later prompt before this work proceeds.
